# 机制提案：互补双代理打分器（CombinedScorer）

> 2026-09-05 提交，走"战役→主线机制提案门"。评审通过后落点
> `evo2/engine/combined_scorer.py`。四段式（恢复方案 §4-原则三）。

## 1. 实战暴露问题

单一代价层代理无法同时把"结合强度"与"条件特异性"预测好：v7 DL 在 n100 干净标签上
act/dual/dcat 全面超 v4（+0.770/+0.838/+0.748 vs +0.739/+0.747），但 sep（靶/非靶
分离度）彻底失败（−0.124 vs v4 +0.330）；反过来 v4 的 act 拟合弱于 DL。根源是结构性
的：特异性需要"DNA 条件差分"的显式归纳偏置（GBM 对条件分裂 + 手工位点簇/电荷特征），
DL 从原始 token 学不出；而强度拟合受益于 DL 的容量。.sep 失败诊断与 A1/A2 消融见
`evo2/results/dl_v7sep/ablation_report_ep12/24.md`。

## 2. 证据（n100，v4×DL 共同覆盖 30 系统）

- 互补前提：DL_act 与真 sep 相关仅 +0.082——强结合的候选未必特异，单维度排序必然
  误判（RD_POS：DL_act 排名 1.0 最高，真 sep 仅 0.01）。
- 组合对比（金标准 = 真 sep）：

| 信号 | rho |
|---|---|
| DL_act 单用 | +0.082 |
| v4_sep 单用 | +0.606 |
| **min(rank(DL_act), rank(v4_sep))** | **+0.630（全组最高）** |
| 加权和 / 乘积 | 低于 min |

- 反例验证：RD_POS（假特异：结合强、不特异）被 min 组合正确压后；已入选 MD 的
  s13_c1 组合分 0.767 进前二。数据：`evo2/results/dl_v7sep/combine_result.csv`。
- 用户拍板（2026-09-05）："组合互补使用，工具好用、有用就行。"

## 3. 一般机制（蛋白无关）

**当一个适应度维度需要显式归纳偏置、另一维度受益于模型容量时，不用单一模型追逐
双指标，而用两个各擅其长的代理分别评分，按 min-rank 组合——两维都高才推荐，
单高被惩罚。**

接口抽象：任何强度代理（现在 DL A1，未来任何模型）与任何特异性代理（现在 v4 GBM，
未来任何模型）只要实现 `score(id) -> float` 同一协议，即可装入组合器；组合规则
（min/加权和/乘积）可配置，默认 min（概念验证最优）。

## 4. 落点模块

- `evo2/engine/combined_scorer.py`：`CombinedScorer` + `percentile_rank`，纯函数式，
  无模型依赖（代理以可调用对象注入），便于战役与主线漏斗共用。
- 回归测试 `evo2/engine/tests/test_combined_scorer.py`：用 combine_result.csv 真实
  数字锁定行为——组合 rho ≥0.60 且不低于任一单用；RD_POS 组合分 <0.4；
  s13_c1 进 top-2。
- 消费方：PprI 战役下一轮候选提名（9/7 MD 收官后）`from evo2.engine.combined_scorer
  import CombinedScorer`；主线 funnel mid 层（v2 方案 M5）的同位接口。
- 边界：本机制不改变 v4/DL 训练管线；sep 金标准仍是 Boltz/MD 代理，组合器只负责
  便宜层上的排序与压伪。
