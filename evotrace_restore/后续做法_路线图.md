## R1 — 自然语言 → EnvSpec 编译器 v0（对应 v1 §3.1，验收线 1）

v1 的第一句话定位至今是零代码，这是第一优先级。

做法（严格按 v1 §3.1 的隔离原则——LLM 只产参数不产数值）：

1. `evo2/engine/envspec/schema.py`：EnvSpec JSON Schema（physics / fitness_weights /
   hard_gates / dynamics / safety 五层），以 `campaigns/ppri_evo/config/envspec.json`
   为第一个校验实例。
2. `evo2/engine/envspec/vocabulary.py`：环境词表 v0，20 条（温度/pH/盐/离子/氧化/压力/
   溶剂/宿主/世代时间/事件脚本……），每条绑定"有据可依的适应度机制"，无机制的显式
   标注 `mechanism: none` 并向用户披露（防幻觉条款，v1 §3.1）。
3. `evo2/engine/envspec/compiler.py`：LLM 函数调用式编译入口。输入自然语言一句话，
   输出 Schema 合法的 EnvSpec + 交互确认界面（CLI 即可）。编译器不做任何数值预测，
   数值全部来自词表绑定机制。
4. 用 v1 用户故事原句做验收：*"让源自嗜热菌的碱性蛋白酶，在高盐碱地环境（5 M NaCl、
   pH 9.5、60 ℃、高浓度 Mg²⁺）中生存一万年"* → 编译出的 EnvSpec 逐字段人工核对。

**出口标准**：20 条词表全覆盖测试句；schema 校验 100% 通过；错例（"磁场"类无机制参数）
正确标注 ignored。

## R2 — 长时程内核演示（对应 v1 §3.4–3.5，验收线 2）

现有 `kernel.py` 已向量化（Ne=500×4 群×15 代×254 位点 1.1 s），差的是时间尺度和事件。

1. **嵌入缓存体系**（v1 §3.2 关键决策 2，"万年模拟的可行性核心"）：离线对种子家族
   1–2 突变邻域预计算表征建库（FAISS/sqlite 即可），运行时命中缓存查表、未命中才调
   模型。先用 avGFP（51k 变体，本地可全量）做缓存命中率实测。
2. **事件脚本 v0**：`evo2/engine/events.py` —— 瓶颈、环境渐变（盐 ramp）、迁移三种，
   时间轴以"代"为单位，年轴换算按 v1 §3.5 三情景并行报告。
3. **首次长时程演示**：avGFP 景观上诚实模式跑 10⁴–10⁵ 代 × Ne=10³，记录缓存命中率、
   墙钟时间、固定事件——产出"单节点跑多长"的实测数据，校准 v1 §3.5 的可行性估算。

**出口标准**：一次 ≥10⁴ 代的完整轨迹落盘；缓存命中率 >99%（v1 预期）；墙钟在单节点
天级以内；轨迹可精确重放（种子+模型版本+EnvSpec 哈希入库，v1 §5 可复现性条款）。

## R3 — 进化产物输出层（对应 v1 §1.1 用户故事 2/4，验收线 3）

1. `evo2/engine/lineage.py`：谱系树记录（每代奠基者-后代边表）→ Newick/JSON 导出 +
   简单树渲染（ECharts 或 ASCII 起步）。
2. 事件时间线：突变固定事件、瓶颈、环境变化按代排列输出。
3. 叙事报告模板：哪个突变先固定、为何被选、平行种群重合率、(μ, σ) 置信区间、
   OOD 距离——Markdown 起步，不做前端。
4. 平行进化统计已有（`metrics.py`、b3），接进报告即可。

**出口标准**：一次 R2 轨迹自动产出：谱系树文件 + 时间线 + 叙事报告，三件套齐全。

## R4 — L3 自然进化回放（对应 v1 §3.7，验收线 4）

五层验证中 L1/L2/L5 已有基准，缺 L3：给家族 MSA"截断时间"，前向模拟后与 ASR 重建

1. 选一个 MSA 充足的家族（avGFP 或枯草杆菌蛋白酶，v1 附录建议的锚点家族）。
2. 截断回放 + KS/Potts 比对脚本，进 `evo2/benchmarks/b8_natreplay.py`。

**出口标准**：距离分布 KS p>0.05、二阶耦合统计一致（v1 通过标准），或如实记录失败
并分析原因。

## 与战役线的关系

- PprI / nom2 战役在 `campaigns/` 里按自己的节奏继续（n=100 标签重测 DL、nom2 扫描
  回收等），**与主线互不阻塞**。
- 战役资产对主线的复用总账在 `复用方案_既有资产最大化利用.md`：v4 GBM 进漏斗 mid 层、
  集群工具链进 R2 缓存体系、7400 行标签进回归测试、DL 负结果进设计约束、nom2 进
  M4 泛化性证据——**之前做过的每一块都有明确去处，隔离不等于作废**。
- 战役对主线的贡献方式有两种：资产领用（上表）与机制提案。机制提案以"实战暴露问题→
  证据→一般机制→落点模块"四段式写进 `evotrace_restore/`，评审后进 `evo2/engine/`——
  而不是直接往 benchmarks/ 塞脚本。这是 8 月底那次漂移的制度性防线。
